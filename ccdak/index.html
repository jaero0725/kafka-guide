CCDAK

CCDAK 개요와 4주 학습 플랜

CCDAK(Confluent Certified Developer for Apache Kafka)는 Kafka를 쓰는 애플리케이션 개발자를 대상으로 하는 자격증입니다. 운영·구축 중심의 CCAAK와 달리 프로듀서·컨슈머 설정, 전달 보장, 스키마, Connect, Streams, 그리고 그 코드를 어떻게 관측하고 테스트하는지를 묻습니다. 이 페이지는 시험 구성을 정리하고, 6개 도메인을 이 사이트의 어느 챕터로 학습할지 매핑한 뒤, 4주 안에 완주하는 순서를 제시합니다.

이 페이지를 읽고 나면

  • CCDAK의 시험 형식과 공개된 정보 / 공개되지 않은 정보를 구분할 수 있습니다.
  • 6개 도메인의 가중치와, 어느 도메인에 시간을 더 써야 하는지 판단할 수 있습니다.
  • 도메인마다 이 사이트의 어느 장·예제·케이스를 읽어야 하는지 찾아갈 수 있습니다.
  • 4주 학습 플랜에 따라 오늘 무엇을 할지 정할 수 있습니다.

시험 개요

시험은 60문항 / 90분이고 지문과 선택지가 전부 영어입니다. 이 두 가지가 준비 전략을 크게 좌우합니다 — 문항당 평균 90초이고, 한국어로만 연습하면 실전에서 읽는 속도가 떨어집니다. 아래 "시험은 전부 영어입니다"를 먼저 읽어 주세요.

반면 합격 점수는 Confluent가 공개하지 않습니다. 인터넷에 도는 "70점 합격" 같은 숫자는 공식 근거가 없으므로 이 사이트에서는 사실로 쓰지 않습니다. 합격선을 모른다고 전제하고, 도메인별로 고르게 올리는 편이 안전합니다.

Confluent는 자격증 시험을 "90 minute proctored exams. Question types vary, and include multiple-choice, matching, list order."라고 안내합니다. 즉 연결형(matching)과 순서 배열형(list order)이 함께 출제됩니다.

  • matching — 설정명↔기본값, 설정명↔소속(프로듀서·컨슈머·브로커·토픽), 예외 클래스↔원인, SMT↔용도, 호환성 모드↔배포 순서 같은 짝짓기입니다. "대충 알면 찍을 수 있는" 객관식과 달리 전부 맞아야 정답이므로 어중간한 암기로는 점수가 안 나옵니다.
  • list order — 트랜잭션 API 호출 순서, kafka-reassign-partitions의 --generate → --execute → --verify, 스키마 진화 배포 순서처럼 절차의 순서를 묻습니다.

객관식만 연습하면 세 유형 중 둘을 시험장에서 처음 보게 됩니다. 이 사이트의 문제 엔진은 세 유형을 모두 지원하므로 연습 단계에서 반드시 섞어서 풀어 두세요.

이 사이트의 모의고사 4세트는 실제와 같은 60문항 / 90분으로 구성됩니다. 그러니 모의고사 점수와 소요 시간을 그대로 실전 지표로 쓰셔도 됩니다. 다만 합격 점수는 여전히 미공개이므로, 이 사이트가 보여 주는 퍼센트는 자체 기준의 참고값입니다. 합격선을 맞히려 하기보다 도메인별 최저점을 끌어올리는 방향으로 쓰는 편이 맞습니다.

그리고 실전은 영어입니다. 90초 중 상당 부분이 읽는 데 쓰이므로, 한국어로 90분에 맞췄더라도 실전에서는 더 빠듯합니다.

시험은 전부 영어입니다

지문·선택지·해설이 모두 영어입니다. 한국어 자료로만 공부하면 개념은 알아도 문장을 해석하는 데 시간을 쓰게 됩니다. 문항당 90초에서 30초를 읽기에 더 쓰면 60문항 기준으로 30분이 날아갑니다. 그래서 이 사이트는 다음 두 가지를 지킵니다.

  • 설정명·클래스명·예외명·CLI 옵션은 번역하지 않습니다. max.poll.interval.ms, ConfigException, kafka-consumer-groups.sh 처럼 시험에 나오는 형태 그대로 씁니다. 한글로 풀어 쓴 자료로 외우면 실전에서 못 알아봅니다.
  • 영어 원문 용어를 함께 적습니다. "리밸런스(rebalance)", "컴팩션(compaction)" 처럼 처음 나올 때 병기합니다.

출제 문장은 몇 가지 틀을 돌려 씁니다. 이 틀만 눈에 익혀도 읽는 속도가 붙습니다. 특히 지시문에서 몇 개를 고르라는지를 놓치면 맞힐 문제를 틀립니다.

이 사이트의 852문항은 한국어입니다. 개념을 정확히 잡는 데는 그편이 빠르지만, 영어로 읽는 훈련은 되지 않습니다. 그래서 실전 감각을 맞추려면 시험 2~3주 전부터 Apache Kafka 공식 문서를 번역 없이 영어 원문으로 읽으세요. 이 사이트의 각 페이지 하단 "공식 문서 출처"에 걸린 링크가 그대로 그 훈련 자료입니다.

특히 설정 설명문(producer configs·consumer configs 페이지)은 시험 문장과 어휘가 거의 겹칩니다. 기본값을 확인하러 갈 때마다 설명문 한 문단씩 영어로 읽는 습관을 들이면 따로 시간을 낼 필요가 없습니다.

위 가중치는 공개 자료 여러 곳에서 일치하는 값이지만, 이 사이트를 만든 환경에서는 Confluent 공식 Exam Guide 문서에 접근할 수 없었습니다. 따라서 잠정치로 간주하고, 응시 전에 Confluent 공식 Exam Guide로 반드시 재확인하세요. 가중치가 바뀌어도 학습 순서의 큰 그림(개발 도메인 우선)은 달라지지 않습니다.

Application Development(28%) + Fundamentals(23%) = 51%입니다. 이 두 도메인에서 실점하면 나머지 네 도메인을 다 맞혀도 위험합니다. 반대로 Application Testing은 8%이므로, 여기서 완벽을 추구하며 며칠을 쓰는 것은 손해입니다. Testing은 도구 선택 기준 표 하나를 외우면 대부분 해결됩니다 (Application Testing 도메인).

4주 학습 플랜

하루 1~2시간, 주 5일을 전제로 한 4주 플랜입니다. 0주차(시작 전)에 진단 테스트 30문항을 먼저 푸세요. 도메인별 정답률이 나오면 아래 플랜의 순서를 자기 약점 순으로 바꿀 수 있습니다. 가중치가 큰 도메인이 약하면 그것이 최우선입니다.

도메인 정답률이 60% 미달이면 그 도메인은 "집중 학습"입니다. 다음 주차로 넘어가지 말고 해당 장을 다시 읽고 함정 사전의 그 도메인 구역을 반복하세요. 60~80%는 "보강"이며 함정 사전 + 문제 절반으로 충분합니다. 80% 이상은 "유지"이므로 모의고사에서만 점검하면 됩니다. 이 판정은 진단 테스트 결과 리포트가 자동으로 계산해 줍니다.

1주차에 4장을 완벽히 하려다 3주차에 Connect·Streams를 못 보는 것입니다. Connect 15% + Streams 12% + Testing 8% = 35%로, 이 세 도메인을 버리면 합격선을 넘기 어렵습니다. 1~2주차는 70~75%를 목표로 하고 넘어간 뒤, 4주차에 되돌아오는 편이 총점이 높습니다.

시험 신청과 응시 준비

  1. Confluent 자격증 포털에서 계정을 만들고 CCDAK를 선택합니다. 응시료는 USD 150이며, 결제 후 일정 기간 안에 응시 일정을 잡는 방식입니다. 바우처·할인 정책은 수시로 바뀌므로 공식 페이지에서 확인하세요.
  2. 프록터링 환경을 미리 점검합니다. 웹캠·마이크·안정적인 상향 대역폭이 필요하고, 책상 위에 다른 물건이 없어야 합니다. 시험 시작 전 방을 카메라로 비춰 보여 주는 절차가 있습니다. 상세 체크리스트는 시험 당일 전략에 있습니다.
  3. 신분증을 준비합니다. 영문 이름이 신청 정보와 일치해야 합니다.
  4. 응시 직전 90분 리허설을 한 번 합니다. 모의고사 세트를 시험 모드로 풀어 "90분 안에 끝내는 페이스"를 몸에 익히세요.
  5. 합격하면 2년 유효합니다. 불합격 시 7일 뒤 재응시할 수 있습니다.

응시 절차의 세부 단계(포털 화면 구성, 바우처 코드 입력 위치, 결과 통보 시점 등)는 이 사이트를 만든 환경에서 Confluent 도메인에 접근할 수 없어 확인하지 못했습니다. 위 절차는 공개 자료로 확인된 범위만 적었으며, 실제 신청 화면은 공식 페이지를 따르세요.

공식 문서 출처

시험 형식(90분, 3가지 문항 유형)은 Confluent 공식 문구에서 확인했습니다. 도메인 가중치는 공개 자료 복수 출처가 일치하는 값이며 공식 Exam Guide로 재확인이 필요합니다. 기술 사실과 설정 기본값은 Apache Kafka 4.3 공식 문서 기준입니다.

  • Apache Kafka Documentation (4.3) — 전체 기술 사실의 기준
  • Producer Configs — acks, linger.ms, enable.idempotence 기본값
  • Consumer Configs — group.protocol, 타임아웃 4종 기본값
  • Topic Configs — cleanup.policy, retention.ms, max.message.bytes
  • Upgrading Apache Kafka — 4.x 변경 사항, Share Groups 4.2 production-ready
  • Kafka Streams — Testing — TopologyTestDriver, TestInputTopic
