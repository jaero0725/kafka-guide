CCDAK

시험 당일 전략

지식이 충분해도 시험장에서 잃는 점수가 있습니다. 프록터링 준비를 안 해서 시작이 지연되거나, matching 유형을 처음 보고 당황하거나, 한 문제에 10분을 쓰고 뒤쪽을 못 푸는 경우입니다. 이 페이지는 지식 외의 변수를 없애는 것을 목표로 합니다.

이 페이지의 목표

  • 프록터링 환경을 시험 전날 완비할 수 있습니다.
  • 세 가지 문항 유형별로 다른 전략을 적용할 수 있습니다.
  • 90분 안에 전 문항을 검토까지 마치는 페이스를 만들 수 있습니다.
  • 선택지 문장만 보고 함정 후보를 먼저 배제할 수 있습니다.

프록터링 플랫폼의 구체적 요구사항(허용 브라우저, 설치 프로그램, 화면 공유 방식)은 이 사이트를 만든 환경에서 Confluent 도메인에 접근할 수 없어 확인하지 못했습니다. 위 항목은 온라인 프록터링 시험의 일반적인 요구사항이며, 실제 요구사항은 응시 안내 메일과 공식 페이지를 반드시 따르세요.

문항 유형 3종 — 각각 다른 전략

Confluent는 자격증 시험을 "90 minute proctored exams. Question types vary, and include multiple-choice, matching, list order." 라고 안내합니다. 객관식만 준비하면 안 됩니다.

(연결형)		 모든 쌍 일치 확실한 쌍을 먼저 확정해 후보를 줄입니다(제거법). 오답 후보(extra)가 섞여 있을 수 있으니 "남은 것을 억지로 짝지어야 한다"고 가정하지 않습니다.

(순서 배열)		 순서 완전 일치 첫 단계와 마지막 단계를 먼저 고정하고 가운데를 채웁니다. "초기화는 한 번만", "검증은 마지막" 같은 원칙이 대개 답을 결정합니다.

  • 설정명 ↔ 소속 — max.request.size(프로듀서) / message.max.bytes(브로커) / max.message.bytes(토픽) / fetch.max.bytes(컨슈머) / replica.fetch.max.bytes(브로커)
  • 예외 클래스 ↔ 원인 — RecordTooLargeException, NotEnoughReplicasException, IllegalStateException(assign+subscribe), ConfigException(멱등성+in-flight>5), TopologyBuilderException(파티션 수 불일치)
  • SMT ↔ 용도 — ValueToKey, MaskField, RegexRouter, TimestampConverter …
  • 호환성 모드 ↔ 배포 순서 — BACKWARD=컨슈머 먼저 / FORWARD=프로듀서 먼저
  • Streams 연산 ↔ stateless·stateful·리파티션
  • 메트릭 ↔ 의미 — records-lag-max, record-error-rate, UnderMinIsrPartitionCount …
  • 테스트 도구 ↔ 브로커 필요 여부
  • 트랜잭션 — initTransactions(1회) → beginTransaction → send → sendOffsetsToTransaction → commitTransaction (실패 시 abortTransaction)
  • Producer 전송 파이프라인 — 직렬화 → 파티셔너 → RecordAccumulator(배치) → Sender 스레드 → 브로커 응답 → 콜백
  • 파티션 재할당 — --generate → --execute → --verify
  • KRaft 부트스트랩 — random-uuid → format → 기동 → 토픽 생성
  • 큰 메시지 허용 — 토픽 max.message.bytes → 프로듀서 max.request.size → 컨슈머 max.partition.fetch.bytes → 브로커 replica.fetch.max.bytes
  • 스키마 진화 배포 — BACKWARD면 컨슈머 배포 → 스키마 등록 → 프로듀서 배포
  • Connect 실패 조사 — GET /status → worker_id 확인 → 해당 노드 로그 → 로그 레벨 상향 → 수정 → restart
  • 업그레이드 경로 — 2.x → 3.9 → KRaft 마이그레이션 → 4.x

90분 시간 배분

실제 문항 수는 공개되지 않습니다. 아래는 이 사이트의 모의고사 벤치마크인 60문항 / 90분을 기준으로 한 페이스입니다. 문항 수가 다르면 비율만 유지하면 됩니다.

3라운드 전략 — 60문항 기준
라운드시간할 일
1라운드
1회독		 60분
(문항당 평균 60초)		 아는 것만 확정하고 나머지는 표시(flag)하고 넘깁니다. 90초를 넘기면 무조건 표시하고 이동합니다. 코드 판독 문항은 여기서 다 풀려고 하지 마세요.
2라운드
표시 문항		 20분 표시한 문항만 다시 봅니다. 1라운드에서 본 다른 문항이 힌트를 주는 경우가 많습니다 (같은 설정을 다른 각도로 묻는 문항이 섞여 있습니다).
3라운드
검토		 10분 복수 선택 문항의 개수 조건과 matching·ordering의 빈칸을 확인합니다. 여기서 발견되는 실수가 가장 아깝습니다. 단일 선택 문항의 첫 직감을 바꾸는 것은 신중히 하세요.
  1. 모르는 설정값 문항을 오래 붙잡기 — 기억에 없으면 1분을 더 써도 안 나옵니다.
  2. 코드를 먼저 정독하기 — 질문을 먼저 읽으면 볼 곳이 3줄로 줄어듭니다.
  3. 이미 확정한 답을 반복해서 다시 보기 — 표시하지 않은 문항은 3라운드에서 건드리지 않습니다.

그리고 빈칸으로 남기지 마세요. 오답 감점이 있다는 근거는 없습니다. 모르면 함정 패턴을 배제한 뒤 남은 것 중 하나를 고르는 것이 항상 낫습니다.

오답 유도 패턴 6가지

선택지 문장의 형태만 보고 함정 후보를 좁힐 수 있습니다. 더 자세한 분석은 함정 사전의 오답 유도 패턴 절에 있습니다.

함정 선택지의 형태별 특징
패턴신호판단
① 절대적 표현 "항상", "절대", "모든 경우에", "무조건", "완전히 보장한다" Kafka에는 조건 없는 보장이 거의 없습니다. 대개 오답입니다. 단 "오프셋은 파티션 안에서만 의미가 있다"처럼 범위를 한정하는 단정은 정답일 수 있습니다.
② 소속 바꿔치기 "프로듀서의 fetch.max.bytes", "컨슈머의 acks", "브로커의 isolation.level" 설정 이름은 맞고 소속이 틀린 형태입니다. 가장 흔한 함정이므로 설정을 볼 때 소속을 먼저 확인하는 습관을 들이세요.
③ 기본값 미묘 변형 linger.ms=0, session.timeout.ms=10000, message.max.bytes=1048576, group.protocol=consumer 3.x 기준 값이거나 12바이트만 다른 값입니다. 4.x에서 바뀐 5개(linger.ms, acks, enable.idempotence, session.timeout.ms, 메타데이터 저장소)를 특히 조심하세요.
④ 옳지만 답이 아닌 것 "acks=all로 설정한다" (질문은 순서 보장에 대한 것) 사실은 맞지만 질문에 답하지 않는 선택지입니다. "가장 적절한"류 문항에서 주로 쓰입니다. 질문의 목적어를 다시 읽으세요.
⑤ 과잉 조치 "토픽을 삭제하고 다시 만든다", "커넥터를 지우고 재생성한다", "unclean.leader.election.enable=true로 켠다" 증상은 사라지지만 데이터 유실·부작용이 큰 선택지입니다. 시험은 최소 변경으로 원인을 제거하는 답을 정답으로 둡니다.
⑥ 층위 혼동 "EOS를 켜면 외부 DB 중복도 막힌다", "컴팩션은 중복을 즉시 제거한다", "tasks.max를 올리면 항상 빨라진다" 보장의 경계나 동작 시점을 넓혀 놓은 선택지입니다. "어디까지"와 "언제"를 확인하면 걸러집니다.

문제문에 버전이 없는데 선택지에 0과 5, 1과 all, false와 true가 함께 있으면 3.x와 4.x의 기본값 차이를 묻는 문항입니다. 이 사이트의 기준은 4.3이므로 새 값을 고릅니다.

반대로 ZooKeeper·--zookeeper가 등장하는 선택지는 4.0에서 제거된 것이므로 현행 기준에서는 오답입니다. "2.13"이 Kafka 버전으로 서술된 선택지도 오답입니다 — 그것은 Scala 버전입니다 (레거시 부록).

출처와 확인 범위

  • 시험 형식 — 90분 프록터링, multiple-choice · matching · list order 3종: Confluent 공식 문구에서 확인했습니다.
  • 문항 수 · 합격 점수 — Confluent 미공개. 이 페이지의 "60문항 / 90분"은 이 사이트의 연습용 벤치마크입니다.
  • 프록터링 세부 요구사항 — 확인하지 못했습니다 (Confluent 도메인 접근 불가). 일반적인 온라인 프록터링 요구사항으로 서술했습니다.
  • 기술 사실과 설정 기본값 — Apache Kafka 4.3 공식 문서 (Producer Configs, Consumer Configs, Topic Configs, Broker Configs).
  • 오답 감점 여부 — 공개된 근거가 없습니다. "빈칸으로 두지 말라"는 조언은 감점이 없다는 확인이 아니라 정보가 없을 때의 기대값 판단입니다.
